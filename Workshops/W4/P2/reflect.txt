-Class Design and Object-Oriented Programming: 
Designing the Guitar and GuitarStr classes provided a practical understanding of 
object-oriented programming principles such as encapsulation, where data (string materials, gauges, etc.) 
and behaviors (changing strings, restringing, etc.) are bundled within classes.

-Constructor Usage: 
1.Guitar
example:
a.Default Constructor:
This is the default constructor with a default parameter value for the Guitar class. 
If no model name is provided when a Guitar object is instantiated, it defaults to "Stratocaster". 
This constructor initializes m_model to the provided name (with safety ensured by strncpy and manual null-termination), 
and sets up the guitar to have no strings (m_strings is nullptr and m_numStrings is 0). 
This shows how a constructor can offer default initialization while still allowing for customization.
b.Parameterized Constructor:
This overloaded constructor demonstrates the use of constructor delegation (: Guitar(mod)) to first initialize the Guitar object's m_model using the logic defined in the default constructor. 
It then proceeds to allocate memory for and initialize m_strings with the GuitarStr objects provided in strs, 
setting m_numStrings to the given ns. This is a clear example of how to use overloaded constructors to provide additional 
flexibility in object initialization, allowing a Guitar to be created with a predefined set of strings and model name.

-Destructor for Resource Management: 
example:
The Destructor in Guitar Class:
The Guitar class dynamically allocates memory for an array of GuitarStr objects to hold its strings. 
This dynamic allocation is necessary because the number of strings a guitar can have might not be known 
at compile time and could change over the guitar's lifetime. 
Dynamic allocation provides the flexibility needed but also imposes the responsibility to explicitly free 
the allocated memory once it's no longer needed. The destructor fulfills this responsibility by using delete[] 
to deallocate the memory allocated for m_strings.


-The use of the current object within the class's member functions:
Whenever you see a member function being defined or called, it operates on the current object. For example:
const char* GuitarStr::material() const {
    return m_material;
}
In this material member function of GuitarStr, m_material refers to the m_material member of the current GuitarStr object on
 which material() is called. Implicitly, it's equivalent to this->m_material, though you don't need to explicitly write this->.
While the code doesn't explicitly use the this keyword to refer to the current object, it's implicitly the context 
for all member function operations.
